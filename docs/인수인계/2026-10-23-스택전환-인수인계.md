## 다른 PC에서 이어서 시작하기

1. 저장소를 받는다.
   ```bash
   git clone https://github.com/yeunlee1/KeyManager.git
   cd KeyManager
   git switch work/2026-10-23-React-NestJS-전환
   ```
   이미 받아 둔 저장소라면 `git fetch origin` 뒤 같은 브랜치로 바꾼다.
2. **Node.js**는 22.22.3 이상(22 계열), 24.15.0 이상(24 계열), 26 이상 중 하나가 필요하다. 홀수 버전 25는 안 된다.
3. **PostgreSQL**을 설치한다. Windows는 EDB 설치판(18.x, `Windows x86-64`)이 서비스 등록까지 해 줘서 편하다. 압축 바이너리판은 설치 마법사가 없다.
4. 앱이 쓸 DB를 만든다. 테이블은 백엔드가 처음 시작할 때 마이그레이션으로 만든다.
   ```bash
   createdb -U postgres keymanager
   ```
5. 백엔드를 띄운다. `.env`의 `DB_PASSWORD`는 직접 채운다(저장소에 올리지 않는다).
   ```bash
   cd backend
   cp .env.example .env
   npm ci
   npm run dev          # http://localhost:5000
   npm test             # 단위 시험
   npm run test:e2e     # keymanager_test DB를 자동으로 만들어 쓰고 그 안만 비운다
   ```
6. 프론트를 띄운다.
   ```bash
   cd frontend
   npm ci
   npm run dev          # http://localhost:3000
   npm test
   ```
7. npm 11은 패키지 설치 스크립트를 승인 전까지 실행하지 않는다. `@swc/core` 안내가 나와도 스크립트 없이 동작하는 것을 확인했으니 승인하지 않아도 된다.

## 새 기능 요구와 결정 사항

### 요구 (2026-10-23 사용자 설명)

회사 서버와 회사 DB를 두고, 직원 각자가 비밀번호를 꺼내 쓰는 프로그램이다. 저장하는 정보는 세 종류다.

1. 회사 공유 정보: 고객사 DB 접속 정보, 원격 접속 정보 등. 필요한 직원이 받아서 로그인에 쓴다.
2. 개인 정보: 본인 아이디·비밀번호. 서버에 올리되 본인만 본다.
3. 라이선스 키: 한컴·오피스 키 등. 지금 프로그램의 기능이다.

지금 앱은 로그인이 없는 사내 도구(README의 "인증 없음, 의도된 설계")지만, 이 기능이 들어오면 로그인·권한·암호화·열람 기록이 핵심인 보안 프로그램이 된다. 그래서 착수 전에 설계서를 먼저 쓰고 승인받는다.

### 정한 것

| 항목 | 결정 | 의미 |
|---|---|---|
| "본인만 보기" 수준 | **종단 간 암호화** | 브라우저에서 본인 마스터 비밀번호로 암호화한 뒤 올린다. 서버·DB 관리자도 볼 수 없고 DB가 통째로 새도 안전하다. |
| 회사 공유 정보 범위 | **묶음(폴더)별로 볼 사람 지정** | 예를 들어 "고객사 A" 묶음은 담당자만, "사내 서버" 묶음은 개발팀만 본다. 묶음마다 보기만/수정 가능 권한을 나누고 열람 기록을 남긴다(제안). 묶음 키를 구성원 공개 키로 감싸 나눠 준다. |
| 로그인 | **앱 자체 계정 + 마스터 비밀번호 하나** | 관리자가 초대하고, 직원은 첫 접속 때 마스터 비밀번호를 정한다. 로그인용 값과 암호화 키를 따로 유도해 서버는 암호화 키를 모른다(Bitwarden 방식). |
| 꺼내 쓰는 방식 | **웹 복사 버튼 + 브라우저 확장 프로그램 자동 입력** | 복사한 비밀번호는 클립보드에서 30초 뒤 지운다. 확장 프로그램 안에서도 금고 열기와 복호화를 직접 해서 종단 간 암호화를 지킨다. |
| 마스터 비밀번호 분실 | **각자 보관한 복구 키로만 재설정** | 관리자 복구는 두지 않는다. 비밀번호와 복구 키를 모두 잃으면 개인 정보는 영구히 사라진다. 회사 공유 정보는 같은 묶음의 다른 구성원이 키를 갖고 있어 다시 공유받으면 된다. |
| 저장소 | **지금 공개 포크에서 개발** | 비밀값·실제 고객사 정보·회사 설정은 저장소에 넣지 않는다. 개발 중 시험은 가짜 자료로 한다. 회사 서버 배포나 팀 공유가 필요해지면 저장소 이전을 다시 정한다(원본에 라이선스 파일이 없어 옮기려면 원작자 허락이 필요하다). |

### 아직 정하지 않은 것

- OTP 2단계 인증을 넣을지(설계안에는 권장으로 넣기로 했다)
- 확장 프로그램 대상 브라우저(Chrome·Edge 예상)와 배포 방식
- 라이선스 키를 금고에 넣어 종단 간 암호화할지, 지금처럼 서버에서 검색·통계가 되는 형태로 둘지(종단 간 암호화하면 서버 검색·통계가 안 된다)
- 열람 기록의 보관 기간과 관리자 화면 범위
- 이미 있는 오픈소스(Vaultwarden, Passbolt)를 쓸지 직접 만들지에 대한 최종 판단(지금까지는 직접 만드는 방향으로 질문에 답했다)

### 피해야 할 것과 주의

- `designed-by-ai/skills@design-mobile-apps`(순위 17위, 약 981K)는 **쓰지 않는다**. GitHub 별이 19개인데 설치 수만 크고, 스킬 설명서에 API 키를 채팅에 붙여 넣으라는 절차가 있으며 skills.sh 보안 검사(Snyk)에서 HIGH로 지적됐다. 핵심 기능이 유료 외부 서비스(Sleek)로 화면 요구를 보내는 방식이라 범용 디자인 스킬도 아니다. 악성으로 확정한 것은 아니다.
- `impeccable` 최신판은 단순 설명서가 아니라 실행 파일 다운로드(GitHub 릴리스, SHA-256 검증), 편집 훅, **기본으로 켜진 익명 통계 전송**을 포함한다. 끄려면 환경변수 `IMPECCABLE_NO_TELEMETRY=1` 또는 `DO_NOT_TRACK=1`을 설정한다. 통계를 꺼도 새 디자인 방향을 고를 때 `impeccable.style`로 보내는 기능 요청은 남는다(문서는 프로젝트 이름·코드는 보내지 않는다고 설명). 회사 PC에서는 아직 끄지 않았다(사용자 결정 대기).
- `web-design-guidelines`는 쓸 때마다 GitHub에서 최신 지침 파일을 내려받는다.
- 설치는 `npx skills add <저장소> --skill <이름>`으로 하고, 설치 전에 SKILL.md를 읽어 외부 전송·설치 스크립트가 있는지 본다.

## 이번 단계에서 고치지 않고 남긴 것

- 등록 창을 닫았다 다시 열면 이전 입력값이 남는다. 원래 앱부터 있던 동작이라 새 디자인 때 다룬다.

- 실제 휴대폰, Firefox·Safari, Node 22·26 실행은 확인하지 않았다(회사 PC의 Node 24.21과 Edge 계열에서만 확인).
