# KeyManager 프론트 표준

이 문서는 KeyManager 화면을 만들고 고칠 때 따르는 기준이다. 색·글자·간격 같은 디자인 토큰, 기본 컴포넌트, 화면 패턴, 코드 규칙, 검증 절차를 한곳에 정한다. 먼저 KeyManager에서 쓰면서 실제 화면으로 다듬고, 검증되면 회사 웹 프로젝트 공통 표준으로 넓힌다.

- 분위기는 **밝고 친근한 SaaS**다(Notion·Stripe처럼 여백이 넓고 부드러운 화면). 처음에는 라이트로 열리고, 다크는 사용자가 고를 수 있다. 포인트 색은 **인디고**다.
- 기본 컴포넌트는 **coss ui**(Base UI 기반, MIT)를 쓴다. 기존 Radix·sonner 기반 컴포넌트는 `components/legacy`로 옮겨 두었고, 새 디자인 단계에서 화면을 하나씩 바꾼 뒤 지운다.
- 토큰과 컴포넌트를 눈으로 보는 **견본 화면**은 개발 서버에서 `http://localhost:3000/standard.html`로 연다. 운영 빌드에는 들어가지 않는다.
- 결정 근거는 2026-10-29 사용자 결정과 같은 날의 현황 점검이다(아래 "지금 화면의 문제"). 이 표준이 지금 화면의 문제를 이미 고친 것은 아니다. 고치는 일은 새 디자인 단계(tm 작업 4)에서 한다.

## 핵심 규칙

1. **프론트 작업은 우리 스킬 `frontend-quality`로 한다.** 자료는 다섯 사이트에서 화면 목적에 맞는 것만 고른다. 입력·메뉴·대화상자 같은 기본 조작 요소는 coss ui, 진행·상태·결과 표현은 Beautiful UI를 먼저 본다. `frontend-design`(디자인 방향), `ui-ux-pro-max`(사용성·접근성 기준), `web-perf`(성능 측정)는 스킬이 정한 보조 역할로만 쓴다. 각자 마음대로 새 방식을 들이지 않는다.
2. **색은 토큰 이름으로만 쓴다.** `bg-primary`, `text-muted-foreground`처럼 쓰고, `slate-500`·`blue-600` 같은 Tailwind 기본색을 화면 코드에 직접 쓰지 않는다. 현황 점검에서 기존 화면은 색 지정의 84.4%(379회)가 기본색 직접 사용이었고, 그래서 테마를 바꿀 때마다 화면을 하나하나 고쳐야 했다.
3. **기본 조작 요소는 `components/ui`(coss ui)에서 가져다 쓴다.** 버튼·입력·선택·대화상자를 화면마다 새로 만들지 않는다. 필요한 것이 없으면 coss ui에서 먼저 찾아 추가한다(아래 "컴포넌트 추가").
4. **글자는 읽히게 쓴다.** 본문 Pretendard, 라이선스 키처럼 한 글자씩 대조하는 값은 JetBrains Mono를 쓴다. 가장 작은 글자는 12px(`text-xs`)이고 9~11px 같은 임의 크기를 쓰지 않는다. 흐린 글자(`text-muted-foreground`)는 설명에만 쓰고, 키·사용자명 같은 핵심 값에는 쓰지 않는다. 글자 대비는 4.5:1 이상이어야 한다.
5. **상태는 글자와 색을 함께 쓴다.** 불러오는 중, 정상적인 빈 결과, 검색 결과 없음, 실패를 서로 다른 화면으로 보여 준다. 실패를 빈 목록처럼 보이게 두지 않는다.
6. **되돌리기 어려운 작업은 확인창을 거친다.** 입력이 필요한 작업은 Dialog, 삭제 같은 확인은 AlertDialog를 쓴다. 닫으면 초점이 연 버튼으로 돌아와야 한다(coss ui가 해 준다).
7. **누구나 조작할 수 있게 만든다.** 모든 입력에 보이는 라벨을 붙이고, 아이콘만 있는 버튼에는 `aria-label`로 이름을 붙인다(툴팁은 이름을 대신하지 않는다). 선택 상태는 탭이나 `aria-pressed`로 알린다. 키보드만으로 모든 작업을 할 수 있어야 한다.
8. **1440·768·390px에서 깨지지 않게 만든다.** 페이지 전체가 가로로 넘치면 안 된다. 넓은 표만 안쪽에서 가로로 스크롤한다. 작은 화면에서는 검색·등록 같은 핵심 행동이 위에 보여야 한다.
9. **움직임은 상태 변화를 이해시킬 때만 쓴다.** 연결됨·사용 중처럼 오래 유지되는 상태에 반복 애니메이션(ping·pulse)을 붙이지 않는다. `transition-all` 대신 바뀌는 속성만 전환한다. 운영체제의 움직임 줄이기 설정을 켠 사용자에게는 `index.css`의 전역 규칙이 애니메이션과 전환을 멈춘다(로딩 아이콘·스켈레톤 포함). 그래서 로딩은 움직임만으로 알리지 않고 글자나 `aria-label`을 함께 둔다.
10. **화면과 화면 읽기 문구는 한국어로 쓴다.** coss ui 원본에 있던 영어 문구(닫기, 이전·다음, 불러오는 중 등)는 한국어로 바꿔 두었다.

## 디자인 토큰

토큰은 `frontend/src/index.css`에 있다. `:root`가 라이트, `.dark`가 다크 값이고, `@theme inline`이 Tailwind 이름(`bg-background` 등)에 연결한다. 색 체계는 coss ui의 `@coss/colors-neutral`을 그대로 쓰고, KeyManager가 바꾼 것은 포인트 색(primary·ring), 위험 색(destructive), 모서리(radius)뿐이다. 위험 색은 coss 기본값(red-500)이 흰 글자와 약 3.8:1(다크 약 3.5:1)이라 대비 규칙을 못 지켜서 red-600으로 바꿨다.

**주의할 뜻 차이**: coss ui에서 `destructive-foreground`·`success-foreground`·`warning-foreground`·`info-foreground`는 "그 색으로 쓴 글자"(예: 빨간 오류 문구)를 뜻한다. 옛 shadcn 방식의 "그 색 바탕 위에 올리는 글자"가 아니다. 그래서 빨간 바탕(`bg-destructive`) 위 글자는 `text-white`로 쓴다. 옛 컴포넌트를 옮길 때 `bg-destructive text-destructive-foreground` 조합이 있으면 바꿔야 한다(옛 위험 버튼에서 실제로 다크 대비 1.22:1이 나왔다).

### 색

| 토큰 | 쓰임 | 라이트 | 다크 |
|---|---|---|---|

| `card`, `popover` | 표·팝업 바탕 | 흰색 | 바탕보다 조금 밝게 |

| `secondary`, `muted`, `accent` | 보조 버튼, 약한 바탕, 마우스를 올린 항목 | 검정 4% | 흰색 4% |
| `muted-foreground` | 보조 설명 글자 | neutral-500 계열 | neutral-500 계열 |

### 글자

| 역할 | 클래스 | 예 |
|---|---|---|
| 페이지 제목 | `font-heading font-semibold text-2xl` | 라이선스 |
| 구획 제목 | `font-heading font-semibold text-lg` | 카테고리별 현황 |
| 본문 | `text-sm` | 표 내용, 설명 문장 |
| 보조 설명 | `text-sm text-muted-foreground` | 마지막 확인 시각 |
| 가장 작은 글자 | `text-xs` (12px) | 표 안의 버전명 |
| 키 값 | `font-mono` | VK7NX-9WQ3M-… |

coss ui 컴포넌트는 휴대폰에서 글자를 한 단계 크게(`text-base`), 데스크톱에서 `sm:text-sm`으로 맞춰 둔다. 화면 코드에서 이 크기를 다시 덮어쓰지 않는다.

### 간격·모서리·그림자

- **모서리**: 기준 `--radius`는 0.625rem(10px)이다. `rounded-sm`·`md`·`lg`·`xl`이 이 값에서 계산되므로, 직접 `rounded-2xl`이나 `rounded-[14px]`를 쓰지 않는다. 동그란 모양이 필요할 때만 `rounded-full`을 쓴다.
- **간격**: Tailwind 기본 간격 단계만 쓴다(`gap-2`, `p-4` 등). 페이지 좌우 여백은 `px-4 sm:px-8`, 최대 폭은 `max-w-6xl`이다. 영역 사이는 `py-10` 정도로 넉넉히 둔다.
- **영역 나누기**: 영역마다 상자(카드)를 겹겹이 두르지 않는다. 간격과 `Separator`로 나누고, 상자는 표·빈 상태처럼 경계가 필요한 곳에만 쓴다. 브랜드와 무관한 그라데이션·유리 효과·배경 글로우는 쓰지 않는다.
- **그림자**: coss ui 컴포넌트에 들어 있는 그림자를 그대로 쓴다. 화면 코드에서 `shadow-2xl` 같은 큰 그림자를 새로 붙이지 않는다.

## 컴포넌트

`frontend/src/components/ui`에 coss ui 컴포넌트 24개가 있다(설치 때 따라온 `scroll-area`·`segmented-control` 포함 26개 파일). 사용법은 [coss ui 문서](https://coss.com/ui/docs)를 따르고, 견본 화면에서 실제 모습을 확인한다.

| 컴포넌트 | 언제 쓰나 | 주의 |
|---|---|---|
| `Button` | 모든 버튼 | 한 영역에 기본(default) 버튼은 하나. 되돌릴 수 없는 행동은 `destructive`·`destructive-outline`, 보조는 `outline`·`ghost`. 처리 중에는 `loading`으로 중복 클릭을 막는다. 아이콘 버튼은 `size="icon"`·`icon-sm`과 `aria-label`. |
| `Field`, `FieldLabel`, `FieldDescription`, `FieldError` | 입력 하나를 라벨·설명·오류와 묶을 때 | 오류는 입력 바로 아래에 다음 행동을 알려 주는 문장으로 쓴다. |
| `Input`, `Textarea`, `InputGroup` | 글자 입력, 아이콘이 붙은 검색 입력 | 검색처럼 라벨이 화면에 안 보이면 `aria-label`을 붙인다. |
| `Select` | 정해진 선택지 중 하나 | `items`에 `{ label, value }` 배열을 주고 `SelectItem`의 `value`는 값 그대로 쓴다. |
| `Checkbox`, `Switch` | 여러 개 고르기, 켜고 끄기 | `Label`로 감싸 글자를 눌러도 바뀌게 한다. |
| `Dialog` | 입력이 필요한 작업(등록·수정) | `DialogTrigger render={<Button />}`로 열어야 닫을 때 초점이 돌아온다. 내용은 `DialogPanel`에 넣는다(낮은 창에서는 안쪽이 스크롤된다). |
| `AlertDialog` | 삭제처럼 되돌리기 어려운 작업의 확인 | 취소·실행 모두 `AlertDialogClose`. 열면 초점이 "취소"에 먼저 간다. |
| `Menu` | 행마다 붙는 추가 작업(…) | 삭제 항목은 `variant="destructive"`. |
| `Tooltip` | 아이콘 버튼의 보조 설명 | 이름은 `aria-label`로 따로 붙인다. 앱 전체를 `TooltipProvider`로 감싼다. |
| `Table` | 목록 | 넓은 표는 `overflow-x-auto` 영역에 `role="region"`·`aria-label`·`tabIndex={0}`을 주고 최소 폭을 둔다. |
| `Badge` | 상태·분류 표시 | 사용 중 `success`, 미사용 `outline`, 주의 `warning`, 오류 `destructive`, 분류 `secondary`. |
| `Tabs` | 같은 화면의 분류 전환(카테고리) | 밑줄형은 `TabsList variant="underline"`. |
| `SegmentedControl` | 2~4개 중 하나를 고르는 필터(사용 상태) | 고른 항목에 `aria-pressed`와 `data-pressed`를 준다. |
| `Pagination` | 페이지 이동 | 결과가 0건이거나 마지막 페이지면 다음·마지막 이동을 막는다. |
| `Empty` | 빈 결과 | 이유와 다음 행동(필터 초기화, 첫 등록)을 함께 보여 준다. |
| `Skeleton`, `Spinner` | 불러오는 중 | 목록은 자리 모양(Skeleton), 버튼 안 처리 중은 `Button loading`. |
| `toastManager` | 작업 결과 알림 | 앱을 `ToastProvider`로 감싸고 `toastManager.add({ title, description, type })`로 띄운다. 실패 토스트에는 다음에 할 일을 쓴다. |
| `Card`, `Separator`, `Kbd` | 경계가 필요한 묶음, 구분선, 단축키 표시 | 카드는 꼭 필요한 곳에만 쓴다. |

### 컴포넌트 추가

coss ui에 있는 컴포넌트가 더 필요하면 `frontend`에서 아래처럼 추가한다. `components.json`에 coss 레지스트리가 등록돼 있다.

```bash
npx shadcn@latest add @coss/<컴포넌트 이름> --yes
```

추가한 뒤에는 반드시 아래를 확인한다.

- `src/index.css`의 토큰 부분을 CLI가 덮어쓰지 않았는지 `git diff`로 본다. 애니메이션·키프레임 추가는 받아들이되, `:root`·`.dark`의 KeyManager 값(인디고 primary·ring)이 바뀌었으면 되돌린다.
- 새 파일에 영어 화면 문구나 `aria-label`이 있으면 한국어로 바꾸고, 파일 첫머리에 `// KeyManager 변경: …` 줄을 남긴다.
- 화면 목적에 맞는 컴포넌트만 추가한다. coss ui 전체(`@coss/ui`)를 한꺼번에 들이지 않는다.

### coss ui 원본을 고칠 때

`components/ui`의 파일은 coss ui 원본이다. 원본을 고치면 나중에 coss ui를 다시 받아 업데이트할 때 바뀐 부분이 사라진다. 그래서 아래 경우에만 고치고, 파일 첫머리에 `// KeyManager 변경:` 줄로 무엇을 바꿨는지 적는다.

- 한국어 문구로 바꿀 때 (지금 `dialog.tsx`, `pagination.tsx`, `spinner.tsx`)
- 접근성 문제를 고칠 때

모양을 바꾸고 싶으면 원본을 고치지 말고 `className`을 넘기거나, 여러 화면에서 반복되면 `components/` 아래에 우리 컴포넌트를 따로 만든다. ESLint의 `react-refresh/only-export-components` 규칙은 coss ui가 `buttonVariants`·`toastManager` 같은 값을 함께 내보내는 설계라 `components/ui`에서만 꺼 두었다.

## 화면 패턴

### 목록 화면

위에서 아래로 **제목과 주요 행동 → 분류 탭과 필터·검색 → 표 → 페이지 이동**을 쌓는다. 견본 화면의 "목록 화면 예시"가 이 순서다.

- 제목 옆에 전체·사용 중·미사용 개수 같은 요약을 한 줄로 둔다. 큰 통계 카드를 맨 위에 길게 두어 휴대폰에서 검색·등록을 아래로 밀어내지 않는다.
- 필터를 바꿔도 지금 어떤 조건인지 화면에 보여야 한다(선택된 탭, 눌린 필터, 검색어).
- 표의 키는 `font-mono`, 버전처럼 덜 중요한 값은 그 아래 `text-xs text-muted-foreground`로 둔다. 긴 사용자명은 `truncate`와 `title`로 줄이되, 전체를 볼 방법을 남긴다.
- 행의 작업이 두 개 이상이면 `Menu`(…)로 모은다.

### 입력 폼

- 라벨은 입력 위, 설명은 라벨 아래, 오류는 입력 아래에 둔다.
- 여러 칸으로 나눈 입력(예: 5칸 제품 키)은 칸마다 다른 이름을 붙이고(`1번째 칸` 등), 전체를 붙여 넣으면 나눠 들어가게 한다. 가능하면 한 칸 입력에 자동 서식을 쓰는 쪽을 먼저 검토한다.
- 제출 중에는 버튼을 `loading`으로 두고, 실패하면 입력값을 지우지 않는다.

### 상태 표시

| 상태 | 보여 줄 것 |
|---|---|
| 불러오는 중 | 표 자리에 Skeleton 행. 영역에 `aria-busy="true"` |
| 처음부터 데이터가 없음 | Empty: "등록된 라이선스가 없어요" + 첫 등록 버튼 |
| 검색·필터 결과 없음 | Empty: "조건에 맞는 라이선스가 없어요" + 필터 초기화 |
| 불러오기 실패 | 빈 결과와 다른 화면: 실패 이유 + 다시 시도 버튼. 빈 목록처럼 보이게 두지 않는다 |
| 작업 성공·실패 | 토스트. 실패는 이유와 다음 행동을 쓴다 |
| 복사 | 성공은 토스트·아이콘 변화, 실패도 사용자에게 알린다(콘솔에만 남기지 않는다) |

진행 단계나 작업 결과를 길게 보여 줘야 하는 화면(예: 비밀번호 금고의 일괄 작업)은 Beautiful UI의 Loading State·Task Rows를 먼저 참고한다. 서버가 주지 않는 진행률이나 예상 시간은 만들어 보여 주지 않는다.

### 문구

- 존댓말 해요체로 짧게 쓴다. 예: "라이선스를 등록했어요", "등록하지 못했어요".
- 버튼은 무엇을 하는지 동사로 쓴다. 예: "등록", "필터 초기화". "확인"만 쓰지 않는다.

## 코드 규칙

```
frontend/src/
├─ components/ui/        coss ui 원본 (위 규칙대로만 고친다)
├─ components/legacy/    옛 Radix·sonner 컴포넌트. 새 디자인에서 화면을 옮긴 뒤 지운다. 새 코드에서 쓰지 않는다
├─ components/           여러 화면이 같이 쓰는 우리 컴포넌트 (필요할 때만 만든다)
├─ features/<업무>/       업무 화면과 그 화면만 쓰는 컴포넌트
├─ api/                  API 요청과 오류 문구 처리 (화면에서 axios를 직접 부르지 않는다)
├─ types/, lib/          타입, 순수 함수
└─ standard/             프론트 표준 견본 화면 (개발용)
```

- import는 `@/` 별칭을 쓴다(`@/components/ui/button`). `@`는 `src`를 가리킨다.
- 한 파일이 조회·등록·통계·툴바를 모두 맡지 않게 나눈다. 기존 `ItemList.tsx`(598줄, useState 19개)는 새 디자인 단계에서 책임별로 나눌 후보다.
- 회사 공통으로 넓힐 때 옮길 것은 `index.css`의 토큰, `components/ui`, 이 문서의 규칙이다. Windows·MS Office 같은 업무 의미나 API 타입은 공통 쪽에 넣지 않는다.
- 새 상태 관리 라이브러리는 필요가 확인될 때만 들인다. 필터·검색·페이지를 주소(URL)에 남길지는 새 디자인 단계에서 정한다.

## 검증

`frontend-quality` 스킬의 검증 기준(스킬 폴더의 `references/검증기준.md`)에 맞춰 바뀐 범위를 확인한다. 실행하지 않은 검증을 통과로 쓰지 않는다.

| 확인 | 방법 |
|---|---|
| 자동 검사 | `npm run typecheck`, `npm run lint`(경고도 실패), `npm test`, `npm run build`, `npm audit`. 결과는 출력 끝이 아니라 **종료 코드**로 판단한다 |
| 화면 폭 | 1440·768·390px에서 페이지 전체 가로 넘침이 없는지(`document.documentElement.scrollWidth`) 보고, 캡처를 직접 연다 |
| 라이트·다크 | 두 모드 모두 캡처하고 글자 대비를 확인한다 |
| 키보드 | Tab으로 모든 조작에 닿는지, 대화상자를 닫으면 초점이 연 버튼으로 돌아오는지, Escape가 동작하는지 |
| 상태 | 그 화면에 실제로 있는 로딩·빈 결과·실패·비활성 상태를 만들어 본다 |
| 낮은 창 | 390×360처럼 낮은 창에서 대화상자가 화면 안에 들어오고 안쪽이 스크롤되는지 |
| 한국어 | 화면 글자와 `aria-label`에 영어가 남지 않았는지 |

## 지금 화면의 문제

2026-10-29 짝(Codex)이 전환 직후 화면(`a3a68cc`)을 점검한 결과다. 새 디자인 단계(tm 작업 4)에서 이 표준으로 고친다. 전체 근거는 점검 보고서에 있다.

| 문제 | 표준의 해결 방향 |
|---|---|
| 색 지정의 84.4%가 Tailwind 기본색 직접 사용 | 토큰만 쓰기(핵심 규칙 2) |
| 배정된 키·버전 글자 대비 약 2.51:1, 9~11px 글자 | 최소 12px, 핵심 값에 흐린 글자 금지(핵심 규칙 4) |
| 등록창을 닫으면 초점이 사라짐(BODY) | coss Dialog + Trigger로 열기(견본에서 복귀 확인) |
| 낮은 창에서 등록창이 화면 밖으로 벗어남 | coss Dialog의 DialogPanel 안쪽 스크롤(390×360에서 확인) |
| 키 5칸이 모두 "제품 키"로만 읽힘 | 칸마다 다른 이름, 붙여 넣기 처리(입력 폼 패턴) |
| 검색 0건인데 다음·마지막 페이지 버튼이 눌림 | 0건·마지막 페이지에서 이동 막기(Pagination 규칙) |
| 복사 21px, 검색 지우기 18px 버튼 | coss Button 아이콘 크기(데스크톱 28px 이상, 터치 기기에서 44px 영역) |
| 목록 불러오기 실패가 빈 목록처럼 보임, 복사 실패가 콘솔에만 남음 | 상태 표시 패턴 |
| 상태 필터가 색으로만 선택을 표시 | SegmentedControl + `aria-pressed`, Tabs |
| 휴대폰에서 통계 카드가 검색·등록을 아래로 밀어냄 | 목록 화면 패턴(요약 한 줄) |
| 상시 반복 애니메이션, `transition-all` 21회, 움직임 줄이기 미대응 | 핵심 규칙 9, 움직임 줄이기 전역 규칙(견본에서 확인) |

유지할 동작도 있다. 검색·Select의 읽기 이름, 삭제 전 확인, 요청 중 중복 클릭 방지, 수정 실패 시 편집 상태 유지, 실제 table 구조, 정상 빈 목록과 검색 0건의 구분이다. 화면을 coss ui로 옮길 때 이 동작을 잃지 않는다.
